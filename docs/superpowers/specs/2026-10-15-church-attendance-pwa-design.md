# 教会出席与奉献 PWA — 设计文档

日期：2026-10-15
状态：草稿，待确认

## 1. 这是什么，为什么要做

马来西亚一间约 100–200 人的华人教会，需要一个手机 PWA 来：

- 记录主日、小组、活动的出席（取代人工点名 / 手抄）
- 让会友记录自己的奉献金额，并显示教会收款 QR 码
- 让新朋友在门口快速登记，后台知道谁是第一次来，方便跟进
- 之后加入活动报名、公告栏、小组资讯

界面需支持 **华语与英语** 双语切换。

成功的样子：主日门口不排队；财务每月能导出一份 Excel 对账；同工知道本周有哪些新朋友。

## 2. 目标 / 非目标 / 反目标

**目标**
- 两种签到方式都可用：门口签到员扫会友个人 QR 码；会友自己扫教会 QR 码
- 奉献记录只限财务和教会管理员查看
- 导出 .xlsx（Excel 和 Google Sheets 都能打开），出席与奉献可以关联

**非目标（明确不做）**
- App 不处理付款，也不验证钱是否到账；奉献金额由会友自填，财务自行对银行月结单
- 不为没有智能手机的长者另做方案（用户明确说不用考虑）
- 第一期不做实时同步到 Google Sheet（以后需要再加）
- 第一期不做手机推送通知
- 不做 Google 登录（用户选择只用电话号码）

**反目标（即使功能都能用，也算失败）**
- 任何普通会友看得到别人的奉献金额
- 主日门口签到太慢导致排队
- 项目和会友资料只挂在某个人的私人账号下，那个人离开后教会无法接手

## 3. 用户已决定的事

| 事项 | 决定 |
|---|---|
| 平台 | PWA（手机浏览器，可加到主屏幕） |
| 后端 | Firebase（不用 Supabase，因为 Supabase 免费版闲置 7 天会暂停，而教会一周只用一次） |
| 登录 | **只用电话号码 + 短信验证码**。因此 Firebase 必须用 Blaze 方案并绑信用卡 |
| 语言 | 华语 / 英语，可切换 |
| 奉献 | App 显示教会收款 QR 码；会友转账后在 App 自填金额 |
| 收款 QR 码 | 只有教会管理员能上传 / 更换 |
| 奉献记录查看 | 只有财务和教会管理员 |
| 导出 | 一键导出 .xlsx |
| 签到 QR 码 | 每次聚会可选「长期有效」或「限时有效（开始–结束时间）」 |
| 聚会类型 | 主日、小组、活动都计算出席率 |
| 新朋友 | 门口另一个「新朋友 QR 码」→ 简短表格，免登录；之后用同一电话号码登录自动接上记录 |
| 会友身份 | 新朋友 → 常来的朋友 → 正式会友，由管理员手动调整 |
| 家庭成员 | 一个账号可以加家庭成员（名字 + 勾选成人 / 小孩），给共用手机的家人或没有手机的小孩用 |
| 国家 | 马来西亚：电话号码 +60、货币 RM、收款 QR 为 DuitNow、遵守 PDPA 2010 |
| 分期 | 第一期：登录、角色、个人 QR、两种签到、新朋友、奉献、导出、双语。第二期：活动报名、公告栏、小组资讯 |

## 4. 角色与权限

权限必须在服务器端（Firestore Security Rules / Cloud Functions）强制，不能只靠隐藏按钮。

| 角色 | 权限 |
|---|---|
| 会友 | 看自己的个人 QR、自助签到、填自己的奉献、看自己的出席与奉献记录 |
| 签到员 | 扫会友个人 QR 帮其签到；看不到奉献 |
| 小组长 | 为自己小组开聚会、帮组员签到、看自己小组的出席；看不到奉献 |
| 财务 | 看所有奉献记录、导出 Excel |
| 教会管理员 | 以上全部；更换收款 QR；指派角色；调整会友身份；合并重复会友；看新朋友名单 |

一个人可以有多个角色（例如同时是小组长和签到员）。

## 5. 功能描述

### 5.1 登录与个人 QR 码
- 电话号码 + 短信验证码登录，登录后保持登录状态
- 第一次登录要填名字（中/英文名）
- 系统自动生成个人 QR 码（内容是会友 ID，不含电话号码）
- 如果这个电话号码已经有「新朋友」记录，自动接上，不建立新会友

### 5.1a 家庭成员
- 账号持有人在「我的家庭」加成员：名字、勾选「成人 / 小孩」
- 每个家庭成员有自己的出席记录和自己的 QR 码（显示在持有人的 App 里）
- 自助签到：扫教会 QR 后，出现家庭成员勾选清单（默认全选），按一次确认全家签到
- 签到员扫持有人的 QR：同样显示家庭成员清单，默认全选，一按确认；扫家庭成员自己的 QR 则直接签到该成员
- 奉献按账号记录，不分家庭成员
- 家庭成员日后有自己的手机并登录：管理员把该成员「转出」成独立账号，出席记录跟着走

### 5.2 聚会
- 主日：每周自动产生（时间由管理员设定）
- 小组聚会、活动：由小组长或管理员建立
- 每个聚会有自己的签到 QR 码，建立时选「长期有效」或「限时有效」

### 5.3 签到方式 A：签到员扫会友
- 签到员选择当前聚会 → 打开相机连续扫码
- 每扫一个立即显示名字和「✓ 已签到」（或「已经签过」），不用按确认，方便快速连续扫
- 同一人同一聚会只记一次

### 5.4 签到方式 B：会友自助
- 会友扫教会签到 QR 码 → 打开 App → 已登录则直接签到成功
- 限时 QR 码在时间外扫：显示「不在签到时间内」
- 未登录：先登录再自动完成签到

### 5.5 新朋友
- 「新朋友 QR 码」→ 免登录表格：名字、电话、同行家人（可选）、怎样认识教会（可选）、是否同意教会联络
- 表格附 PDPA 个人资料使用说明（双语），须勾选同意才能提交
- 提交后：建立「新朋友」记录，记录首次来访日期，记录当天出席
- 后台「新朋友」页：本周新朋友、第几次来、最近一次出席、多久没来

### 5.6 奉献
- 奉献页：显示教会收款 QR 码 → 会友用自己的银行 App 扫码转账 → 回来填金额 → 提交
- 记录：会友、日期、金额、提交时间
- 会友只看得到自己的记录

### 5.7 导出 Excel
- 财务 / 管理员选日期范围 → 下载 .xlsx，含工作表：
  1. 出席记录：日期、聚会、名字、签到方式
  2. 奉献记录：日期、名字、金额
  3. 合并表：每个会友 × 每个聚会一行，出席与否 + 奉献金额
  4. 出席率：每个会友 / 每个小组在该期间的出席率

### 5.8 第二期（概要，开工前再细化）
- 活动页：详情、报名按钮、名额上限、截止日期；主办方看名单、可导出；活动当天对比「报名未到 / 未报名但到」
- 公告栏：管理员发布，大家打开 App 可看
- 小组资讯：每个小组一页（组长、时间、地点、近期消息）

## 6. 运维与费用约束

- Firebase 项目建议由**教会的 Google 账号**拥有，开发者加为管理员
- Blaze 方案：设预算提醒（例如每月 5 美元），短信只允许发往马来西亚（+60，防短信刷量）
- 预期费用：短信每年几百条；Firestore / Hosting 在免费额度内
- iPhone 加到主屏幕的 PWA 需实测登录流程
- 发往马来西亚的短信单价以 Firebase 官方价格页为准，开工前确认
- 个人资料：遵守马来西亚 PDPA 2010；提供会友查看 / 删除自己资料的方法

## 7. 设计者的判断（用户未明确决定，可推翻）

- **奉献与聚会的关联**：奉献按「会友 + 日期」记录，不绑定某个聚会。合并表中，奉献金额放在同一天的主日那一行；同一天没有主日则另列。导出另有「每会友每期间奉献合计」。
- **奉献类别**：可选类别字段，类别清单由管理员设定，默认只有「一般奉献」。
- **奉献修改**：会友只能在提交当天修改 / 删除自己的记录；之后只有财务可改，每次修改保留记录（谁、何时、原金额）。
- **小组名单**：由管理员或小组长把会友加入小组；一人可属多个小组，一个小组长可带多个小组。
- **门口固定海报**：「教会签到 QR 码」是固定的，扫码后自动对应「现在正在进行的聚会」，所以海报不用每周重印。聚会设定为「限时」时，只在该时间内可签到；没有进行中的聚会时显示提示。
- **新朋友重复来访**：未登录前再次填写新朋友表格，系统按电话号码认出同一人，记为第 N 次来访，不建立新记录。
- **出席率算法**：个人出席率 = 出席次数 ÷ 该期间内他应出席的聚会数（主日：所有主日，从首次来访日起算；小组：他所属小组的聚会）。小组出席率 = 组员个人出席率平均。新朋友不计入正式会友的统计，但可单独查看。
- **重复会友合并**：用于管理员手动建了记录、之后本人又换了电话号码登录等情况。

## 8. 留给开发者决定

- 前端技术：Vite + React + TypeScript；i18n 用简单 JSON 字典
- 后端：Firestore + Firebase Auth（Phone）+ Cloud Functions（新朋友表格提交、电话号码合并、角色指派用 custom claims、签到时间校验）+ Firebase Hosting
- 免登录的新朋友表格经 Cloud Function 写入，并加防滥用措施（App Check / 频率限制）
- 扫码库、QR 生成库、xlsx 生成库（例如 SheetJS）由开发者选
- 门口网络不稳时，签到写入先存在本地，恢复网络后再送出
- 资料结构、页面布局与视觉设计
